# 给 DSH 补上视觉与操作能力：从读视频到操作电脑

这篇是 B34《给大肥鱼装五官：看视频刷B站，一期搭完》的详细学习说明。原片用两分钟介绍七种插件，适合建立能力地图；本篇补读其中三个官方项目，把视频理解、实时陪看和桌面操作如何接起来讲清楚。阅读后应能为自己的助手选择输入工具，并设计一个可检验的最小流程。

## 有什么新东西，能拿来做什么

原先只有文本输入的助手，需要你描述屏幕、复制文章、解释视频中发生了什么。这组插件把资料取得和界面操作变成模型可以调用的工具：取视频分镜、取得字幕、读取链接、观察屏幕、点击和打字。由此可以设计带时间点的视频学习助手、陪你看教程的角色，以及根据当前界面帮助完成操作的助手。

这里有两层能力：工具负责拿到图片、文字或界面元素，模型负责理解并选择下一步。把截图交给纯文本模型，不会自动让它获得图像理解能力；需要可接收图片的模型或额外的视觉识别工具。界面树则可以把按钮名称、文本等直接交给文本模型。这一点决定了接入前应检查什么。

## 视频阅读：为什么分镜、台词和放大需要一起用

字幕告诉你讲了什么，却不一定告诉你点了哪个菜单；画面能显示界面，却没有自动包含口播。dsh-video-storyboard 把二者沿时间轴对应起来，并提供回到局部的工具。与固定间隔截屏相比，它按镜头与画面变化分配采样；与只提供最终摘要相比，模型可以依据原始分镜继续追问具体时刻。

官方 README 当前列出六个工具：`video_probe` 检查时长、分辨率和轨道；`video_storyboard` 生成分镜及清单；`video_zoom` 细看局部；`video_locate` 从文字线索找时间；`video_subtitles` 提取硬字幕区域供阅读；`video_help` 提供参数说明。视频只有功能概述，这些是本次补读资料得到的内容。

开始使用时按以下顺序验证：

1. 准备一段已知内容的本地视频，确认 FFmpeg 和 ffprobe 可用。直接读取本地文件时不依赖链接下载器；远程链接路线另需 yt-dlp。
2. 先用 `video_probe` 确认时长和是否有音轨、字幕轨。没有独立字幕轨，不代表画面没有硬字幕。
3. 调用 `video_storyboard`，先采用默认策略；需要估算图片规模时用 `dryRun: true`。这一步只预分析，不代表已经转写或阅读。
4. 为台词接入 ASR，或者通过 `transcriptFile` 提供已有 SRT/JSON。官方明确指出没有转写就可能只有图，没有台词；先检查一小段是否真实产生文字。
5. 对关键操作调用 `video_zoom`。分镜小格里的菜单文字、错误代码不能靠猜，必须放大确认。
6. 输出“步骤—对应时间—画面证据—解释”，再总结适用场景。

主要参数中，`input` 是文件路径或链接；`from/to` 约束阅读片段；`strategy` 调整图片安排；`detail` 调整每格台词的文字预算；`quality` 影响链接下载清晰度，不会提高本地低清视频的原始细节。官方当前文档采用自动张数预算，不应把旧演示里的固定宫格数当成所有版本的接口。

**自拟案例：读一段三分钟插件安装课。** 先取得完整时间轴与台词，定位“安装后重启”和“找不到依赖”两个片段，再放大读取安装入口与错误提示。最终说明需要写出缺的是哪个程序、在哪个环境可见、成功后出现哪个工具。仅写“装好插件即可使用”不足以让读者复现。

## 实时陪看：变化筛选改善了什么

See Now 将屏幕、摄像头或视频文件转换为变化帧拼图。相比每隔几秒传完整屏幕，静止时可以减少重复图；相比很稀疏的固定截图，它尝试在切换或持续运动时保留更多信息。适合看演示、直播、游戏或观察操作过程。

它仍是采样：变化分衡量像素变化，不直接衡量知识重要性。一行静态代码可能比大面积动画更重要。因此陪看教程时，应允许主动暂停、保留当前原图并放大阅读。需要回溯的学习任务还应持久保存时间与笔记，不能只依赖最近一张拼图。

原片说“静止时几乎不花 token”；官方文档同时列出静态兜底帧和长会话图片历史的问题。准确理解是减少新增重复画面输入，不能据此推导整段对话没有费用。官方的每张图片 token 示例按特定 DeepSeek 图像计费口径计算，不能直接套到 Gemini 或 Qwen。

最小试用可以选一段含静态文档、翻页、弹窗的演示：记录助手能否发现每次变化、能否正确读出错误信息，以及反馈延迟。只看它会不会描述“你在用电脑”，无法判断能否辅助学习。Mac 需要相应录屏授权；摄像头则按实际来源配置权限。

## 桌面操作：从观察到执行，再核对结果

dsh-windows-mcp 将 Windows-MCP 接到 DSH 自带的 MCP bridge。官方要求 Windows 10/11、带对应桥接能力的 DSH Desktop，以及安装依赖所需的 uv。它提供两种观察输入：`Screenshot` 是图片；`Snapshot` 是可访问性界面树。点击、打字、快捷键和滚动是执行动作，之后仍应重新读取界面判断是否完成。

文档给出的安装主线是：在 DSH Desktop 插件设置添加该插件并重启，在 Desktop 设置里安装 Windows-MCP 依赖，再重启，最后在目标会话开启 Computer Use。新会话的开关默认关闭；关闭后相关桌面工具会从该会话隐藏并拒绝调用。这是程序控制开关，不是让模型自行决定是否遵守的提示词。

测试可以从“打开记事本、写入三行指定文本、重新读取确认”开始。成功标准是最终文本和目标窗口正确，不是工具返回了一次点击成功。Windows 工具不能直接用于当前 Mac 桌面；跨平台方案需要另外选择执行端。

**应用推演：让陪伴助手把复杂任务交给另一个工作助手。** 可以设计为：收集目标与项目路径 → 在目标应用中提交清楚的任务 → 记录会话入口 → 等待真正完成或需补充信息 → 读取产物与结果 → 回到用户对话解释。原片说明的桌面工具为这类流程提供了输入动作，但本次没有测试 Gemini 或 Codex 的连接，也没有证明插件可以自动维护长任务状态。若要落地，首先应验证能否稳定定位目标会话和读取完成状态，这比仅能点开应用更关键。

## 怎样为自己的学习助手选组合

已有视频收藏：先组合“视频文件/链接取得 + 转写 + 分镜 + 局部放大”，复用现成素材，避免先引入平台推荐发现。希望发现新内容时，再增加搜索与日报模块。实时陪看才需要持续屏幕捕获；真正代操作时再增加桌面执行工具。Envoy、ModLens 等承担不同输入转换，不必为了凑齐七项一次安装全部。

把这套方法迁到 YonWORK 时，可以保留阅读顺序、笔记结构和验收方法作为 Skill；FFmpeg、ASR、下载器和桌面控制需由实际工具、MCP 或本地服务提供。可调用性应分别确认，不能只复制一份 Skill 就认为运行依赖已就绪。

练习：视频里无字幕、画面是代码、背景有人讲解，该用什么？参考答案：完整音轨转写提供讲解；分镜定位代码变化；原尺寸截图或局部放大确认代码；将两者按时间对应。只有 OCR 会漏口播，只有 ASR 会漏代码。
