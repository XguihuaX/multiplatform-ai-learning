# JoVox 与 MACaQ：更轻的三维结构生成，以及低精度模型的质量改善

这条收藏同时介绍两个独立项目。JoVox 负责图片到三维结构的一段生成过程；MACaQ 负责模型量化。对制作新东西而言，前者可以探索从角色或道具图片取得三维几何，后者可以探索把文本、图像、视频或语音模型部署到更受限的资源中。本篇先说明新能力和比较对象，再给出开始路径。它是技术介绍与入门实践说明，未在本机运行模型。

## JoVox：改善的是结构生成阶段

体素可以理解为三维空间中的小格子，记录哪些位置被物体占据。它描述物体的空间结构；最终可渲染的网格还需要后续步骤。官方 JoVox 使用一个模型联合生成不同粗细层级的结构，介绍为 4³→16³→64³，而非让各个尺度完全独立地逐级生成。公开版本提供以图片为条件的64³体素生成及训练、采样和评估代码。

对于图片生成模型，这里的条件图片相当于“照着这个形象构建结构”。官方完整图片到网格路径还调用 TRELLIS.2 的第二阶段：先去背景及整理输入，再生成体素，最后转换成网格。JoVox 的改善应放在这个流程中看。

### 相比 TRELLIS.2 有什么改善

官方 README 在同骨干网络比较中报告训练吞吐8倍、一次前向计算量0.82对12.2 TFLOPs，以及训练使用4对32张H100。这些描述训练资源与计算，不能直接用作“自己生成一个角色快8倍”的耗时承诺。推理要另外计入去背景、图片编码、结构生成和后续网格生成。

在1000个Toys4k测试物体上，官方列出体素相关Chamfer距离从0.01250降到0.01107，约降低11%；IoU从0.4017升到0.4158。Chamfer距离衡量形状之间的距离，越低越好；IoU衡量占据空间的重叠程度，越高越好。这些让我们知道结构指标改善了什么，但人物脸部、衣服纹理及动画效果仍需检查最终输出。

官方另发布 JoVox-64-Robust，针对输入图中物体大小不同的情况，建议自己的图片优先考虑该更新。它是同一项目的输入鲁棒性改进，不是视频中作者已经完成的新版本测试。

### 原视频里很有价值的实际发现

视频00:38–00:43称右侧JoVox体素形状更好；00:46–00:59随后指出，在作者当时改造的ComfyUI/TRELLIS.2流程中，最终成图反而不好。关键帧确实展示了节点流程、结构预览及两个人物结果，因此需要同时保留这两个观察。

作者01:00–01:10推测与DINO有关，并说明尚未跑通原生TRELLIS.2准备再评测。这是作者对其环境的推测，没有定位到已证明的根因。对我们的启发是：替换结构生成模块后，应同时检查结构本身与完整生成链路，不要只看体素截图或一项指标就判断作品一定改善。

### 怎样开始：先拿到一个可检查的网格

官方环境是Linux、NVIDIA GPU，测试过A100；软件列出CUDA12.4、Python3.10和PyTorch2.6.0，并需编译相关CUDA扩展。当前Mac并非该README验证的原生运行环境。第一次尝试可用符合要求的机器及官方示例图，先确认整个链路跑通，再换人物图。

依赖各有职责：DINOv3编码输入图；RMBG-2.0去背景；JoVox生成结构；TRELLIS.2-4B负责后续网格。LPIPS与DINOv2用于官方评估，不是每次生成都必需的主流程模块。安装和模型准备需按官方固定版本执行；本文仅记录操作说明，没有替读者执行安装。

环境和权重准备后，可以按官方三阶段脚本处理一个目录。以下路径是自拟示例，需对应实际文件：

```bash
python scripts/img2mesh.py --stage prep --model checkpoints/voxelgen64 --in_dir inputs/demo --out outputs/demo
python scripts/img2mesh.py --stage voxel --model checkpoints/voxelgen64 --out outputs/demo --seed 0
python scripts/img2mesh.py --stage mesh --out outputs/demo --seed 0
```

`--stage`选择阶段；`--model`指向包含权重与配置的目录；`--in_dir`是输入图片目录；`--out`同时保存中间结果并供下一阶段读取；`--seed`固定随机种子。三个输出目录分别为`prep/`、`voxels/`、`mesh/`，网格阶段每张图片对应一个`.ply`文件。这样保留中间结果，才便于分清问题出在输入预处理、结构还是后续网格。

**自拟应用案例：为虚拟陪伴角色制作一个桌面摆件。** 先选择轮廓清楚、遮挡较少的道具图，检查去背景后有没有切掉细杆或耳朵；生成结构后从正侧背面检查；再查看网格有无洞、断裂和漂浮碎片。若要把人物用于动作或表情，还需后续拓扑整理、骨骼绑定、蒙皮与表情制作。当前输出网格本身没有证明已提供这些能力。

## MACaQ：在低精度下尽量保留模型行为

量化把模型内部的数值压缩到更少的表示位数，目标是减少权重或运行所需资源，并在有匹配计算实现时加速。代价是引入数值误差。校准使用一批代表性输入，帮助量化过程选择更适合该模型和工作负载的数值表示。

W4A4指权重和激活均采用4位表示；GGUF是模型文件与量化表示的封装路线，不能把所有GGUF都叫作同一种4位计算。硬件能存下低位权重，也不意味着任何低位格式都能得到原生加速。

### 视频描述与当前官方资料要分开读

原片01:12以后转向MACaQ，01:18–01:28重点介绍MXFP4及当时硬件支持，并展示图像/视频生成对比。它是一段快速项目介绍，未给出本机量化命令、完整基准条件或独立复现实验。

本次查阅的官方项目范围更广，提供Diffusers、llama.cpp、vLLM和PyTorch路线，分别覆盖图像/视频/音频、文本生成及服务、语音生成。当前README还明确提供MACaQ-R：在保留原生格式和块缩放的情况下优化已有GGUF的权重编码，输出可由标准llama.cpp运行。完整MACaQ的激活变换路线则需按其配套运行时说明处理。因此不能将视频针对MXFP4的硬件说法概括为整个项目只支持某代显卡。

### 相比已有量化模型，好在哪里

一个相对容易理解的官方比较是同一Qwen3.6-35B-A3B模型：Unsloth UD-Q4_K_XL与MACaQ-R Q4_K_XL文件都为22.36GB，后者相对FP16的KL散度从0.015731降至0.013367。KL反映输出概率分布偏离参考模型的程度，降低意味着在该评估口径下更接近参考模型。这里强调的是同文件体积的质量改善，并没有证明每类问答、中文RP或工具调用都会同步提升。

官方还报告122B模型量化耗时64分钟、设备内存32.5GB，以及特定Llama-3-8B比较中达到相同最佳困惑度时量化耗时减少11倍。首页没有列全这些数字的硬件与测试条件，暂作项目报告结果，不作为购买硬件或估算用户耗时的依据。量化过程耗时、部署时内存和推理速度是三个应分别记录的指标。

### 怎样开始使用：先区分运行与自己量化

**路线一：运行现成MACaQ-R GGUF。** 确认文件确实属于兼容标准llama.cpp的MACaQ-R路线，模型体积适合机器，运行时支持其基础架构。先加载现成文件测试自己的任务；这条路线不要求先自行做校准训练。模型文件体积也不是完整运行内存，仍要留出上下文缓存和运行开销。

**路线二：自己改进量化文件。** 官方示例需要已有量化GGUF、匹配的原模型、FP16教师文件、校准文本、输出路径与工作目录。关键不是填满参数，而是三份模型必须来自匹配的来源；校准文本应代表要部署的任务。

```bash
.venv-llamacpp/bin/python llamacpp/macaq.py refine \
  --model models/model-q4.gguf --hf models/original \
  --teacher models/original-f16.gguf --calibration data/calibration.txt \
  --output models/model-macaq-r.gguf --work-dir work/refinement
```

这段来自官方入口的参数结构，是环境搭建后的调用示例，不是单独一条可完成全部安装的命令。`--model`是待优化文件；`--hf`是匹配原模型目录；`--teacher`提供参考模型；`--calibration`指定校准材料；`--output`是新文件，`--work-dir`保存过程文件。官方建议Python3.12，并为不同后端分设环境。

**自拟应用案例：给本地陪伴助手选量化版本。** 保持角色卡、上下文长度和生成参数相同，分别测试旧量化文件与MACaQ-R文件；记录角色一致性、重复语句、指令遵循、首字延迟、生成速度和峰值内存。校准样本与验收对话分开，避免只在熟悉的样本上显得更好。若模型较小但上下文很长，也要检查缓存是否抵消了权重节省。

语音场景可进一步研究官方PyTorch路线中的Qwen3-TTS或Chatterbox Turbo，但这不是GPT-SoVITS本身的优化，也没有证明可直接替换用户已有的语音链路。需要比较声音质量、首段音频延迟与实际接入方式后再选择。

## 两项技术能怎样组合

JoVox可以探索取得角色或道具的几何资产；MACaQ可以探索降低某个实际模型的部署成本。它们属于不同环节，没有官方证据说明两者已经组成一键角色系统。对于新作品，先完成一个静态道具生成案例，或一个量化模型对照案例，再把已验证的模块接到现有助手中，更容易判断改善来自哪里。

练习：结构指标改善，但人物网格更难看，应先检查什么？参考答案：固定输入图和随机种子，比较预处理图、体素与网格三个阶段，核对后续TRELLIS.2版本和条件输入；不能仅凭最终效果推断JoVox无效，也不能凭结构指标忽略最终失败。
