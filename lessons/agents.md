# Agent 与记忆：让任务接得上，让知识找得到

收藏里“动态记忆”“持续运行”“多 Agent 公司”等展示，最后都要落到三个工程问题：当前应该做什么、过去哪些信息仍有效、做完之后怎样确认结果。本章用“持续维护学习资料的助手”讲清这三个问题。

## 1. 一次对话怎样变成任务循环

最简单的循环是：读取目标与状态 → 选择一个动作 → 执行工具 → 读取真实结果 → 更新状态 → 决定继续或结束。例如读一条视频时，状态不能只写“处理中”，应能回答目前有无媒体、字幕是否可用、哪些段落读过、教程写到哪一步。

```json
{
  "task_id": "learn-tts-001",
  "goal": "整理低延迟TTS接入教程",
  "stage": "write_lesson",
  "artifacts": ["transcript.json", "frame_notes.md", "api_notes.md"],
  "next_action": "补写取消播放与延迟测量",
  "done_when": ["接口有来源", "包含完整案例", "索引链接可用"]
}
```

这个记录是持久状态，进程重启后还能继续。“模型知道我要做什么”和“任务能够恢复”之间的连接，就在这些落盘产物与明确状态里。

## 2. 四种常被混称为记忆的东西

| 类型 | 保存什么 | 例子 |
| --- | --- | --- |
| 当前上下文 | 本次推理直接看见的内容 | 用户刚说要详细的技术教程 |
| 任务状态 | 当前工作的进度与产物 | TTS章节完成，B站长课未完成 |
| 长期知识 | 可供以后检索的稳定内容 | TTFA与RTF的定义和例子 |
| 用户偏好 | 会影响未来决策的偏好 | 按知识类型组织，正文先教会读者 |

全部聊天原文直接塞入上下文，会消耗空间且引入过时信息。可复用记忆需要来源、时间和适用范围。例如“运行快”没有检索价值；“某版本在指定硬件上的TTFA P50，以及测量条件”才可比较。

## 3. 一条记忆如何更新

假设原记录是：“TTS应用采用整段WAV播放。”新需求是“用户说话时应立即停止回答”。更新时应保留决定变化的原因，并让当前方案明确指向流式播放与轮次取消。

```text
主题：学习助手音频播放
当前决定：按短句提交TTS，PCM队列播放；新轮次取消旧任务并清空队列。
原因：需要支持插话，整段播放的交互不满足要求。
替代的旧决定：整段WAV播放，仅保留为第一阶段连通性测试。
来源：本次应用设计。
```

这样下一次检索“播放方案”，AI能得到现行决定，同时知道旧方案为什么还存在。只追加新记录却不处理旧记录的有效性，会让检索结果自相矛盾。

## 4. 检索怎样服务当前任务

建立索引时把一个相对完整的知识单元放在同一块里。例如“TTFA定义＋测量起终点＋例子”应尽量放一起；代码示例不要从前提和字段解释中截断。

查询“如何减少语音助手等待”时，先用主题、平台、模型版本筛出候选，再做关键词或语义检索，将命中的上下文提供给模型。模型回答时保留来源。第一版用Markdown标题和关键词搜索就能工作，材料增多后再引入向量索引。

检索出来的文字是参考材料。材料中出现“执行安装命令”或“忽略此前规则”，不应改变助手的任务授权。代码、提示词和日志都可能是研究对象。

## 5. 多 Agent 何时有帮助

当子任务可独立交付且验收明确时可以分工。例如一个读TTS官方接口，一个整理视频画面，最后由整合者对齐名称与版本。每个子任务应有固定产物，避免三个Agent反复互相聊天而没有新信息。

多Agent还有成本：重复读背景、协调冲突、共享文件覆盖、结论互相引用却没有原始证据。对一条18秒的工具展示，一个助手顺序完成往往足够。对多份独立材料，可以并行采集，然后集中整合。

持续运行也需要停止条件：达到交付标准停止；同一步失败时保留错误和进度；需要新增权限或缺少关键输入时明确报告。不能用“还在思考”代替可观察进展。

## 6. 一个最小可做的作品

做一个“学习任务续接器”：每条任务有目标、阶段、产物路径和下一步；启动时列出未完成任务，选择一个后只读取有关材料，生成下一份产物并更新状态。先用JSON或Markdown保存，不需要数据库。

验收时手动中断程序，再启动：它能否跳过已完成转写，继续补教程？修改一个旧决定后，检索是否优先返回现行方案？这两个实验比把功能命名为“长期记忆”更能说明实际效果。

## 7. 练习与参考答案

**题：同一主题有两条记录，旧记录说用接口A，新记录说改用B，应该删除旧记录吗？** 当前决策指向B，A可以保留为历史，但应标明被替代及原因；检索默认优先现行记录。

**题：Agent日志写“已提交”，是否任务完成？** 要读取工具结果或目标系统回执。对本仓库，写出文件、索引可读、推送成功是不同的可观察步骤。
