# 从角色图到会说话的形象：读懂动画制作管线

这批收藏同时包含角色建模、头发、动作、表情、物理和视频生成。先知道各环节输入输出，才能判断两个工具能否接在一起。本章用“给语音学习助手加一个会动的角色”作为完整设计例子；B03的两小时Blender课程仍需另写逐章操作讲义。

## 1. 先选择最终产物

| 想得到什么 | 通常需要准备什么 | 输出有什么特点 |
| --- | --- | --- |
| 一张会动的二维角色图 | 分层图或可变形网格、控制点、驱动参数 | 正面表现容易，转到侧面可能缺信息 |
| 可多角度使用的三维角色 | 网格、材质、骨骼、权重、表情 | 可复用，但制作与绑定工作更多 |
| 一段生成视频 | 输入图/提示词/运动控制 | 直接得到画面，通常没有可编辑角色骨骼 |

例如只想让桌面角色开口说话，可以先用二维嘴型与轻微头部运动，不必先完成完整三维人物。若想导入游戏并让角色走路、转身，则要检查模型、骨骼和动画格式。

## 2. 三维角色各部分如何配合

网格决定形状；材质与贴图决定表面颜色、粗糙度和光照响应；骨骼提供控制结构；蒙皮权重决定每个顶点跟随哪些骨骼移动。动画是一组随时间改变的控制值。表情常用形态键/Blendshape改变脸部形状；头发、裙摆等还可能受物理模拟驱动。

因此“生成了好看的角色”只证明某个输出好看。要做动作，还要看模型是否有合适骨骼、权重是否合理；嘴型则要看是否有可驱动的嘴部形状。

检查两个工具能否衔接时，列出接口：文件格式、坐标与单位、骨骼名称和层级、表情通道名称、材质支持。仅因为都写“支持3D”并不能推导可以直接互用。

## 3. 二维角色怎样动起来

X02展示的方向是把插画转成可驱动形象。一般思路是在图片上建立网格或控制点，让头、眼睛、嘴等区域按参数变形。系统再把音频或摄像头信号映射到这些参数。图片看不见的区域没有现成纹理，大幅转头时会暴露二维表示的局限。

一个最小口型系统可以只准备三张嘴图：闭嘴、半开、张开。对正在播放的PCM计算短时间窗能量，用它控制嘴巴开合。

## 4. 完整算例：音量驱动嘴型

对一窗N个归一化音频采样x，均方根音量为：

```text
rms = sqrt(sum(x[i] * x[i]) / N)
open = clamp((rms - silence_floor) / (loud_level - silence_floor), 0, 1)
smoothed = 0.7 * previous + 0.3 * open
```

`silence_floor`是静音底噪阈值，`loud_level`是正常较响语音的参考量级。平滑能减少嘴型抖动，但过强会造成跟随迟缓。参数从自己的音频统计取得，不应照抄一个固定值适用于所有声音。

将平滑值0～0.2映射闭嘴、0.2～0.6映射半开、其余映射张开，即可做出第一版。这个方法跟随的是音量，无法准确区分“啊”“呜”等音素；需要更细口型时，再引入音素时间对齐和对应嘴型。

最重要的是用**实际播放到的音频时间**驱动画面。若声音还在网络缓冲，嘴已根据刚收到的数据动起来，就会提前开口。取消回答时同时清空音频队列并把嘴型归零。

## 5. 从原型逐步增加效果

第一步做固定音频＋三张嘴图，验证同步。第二步接TTS流，将播放器读出的采样喂给口型模块。第三步加入独立眨眼和轻微头部运动。第四步才考虑情绪到表情映射，例如“强调”配合眉毛变化；不能把每个词都变成夸张动作。

若后续换三维角色，可保留音频与时间管理模块，将 `open` 从二维图片选择改成某个嘴部Blendshape权重。这样“信号产生”和“角色渲染”分开，替换模型更容易。

## 6. 验收与练习

连续播放一句话后静音，嘴是否停下？暂停音频后画面是否同步暂停？用户打断回答后是否还残留嘴部动作？这三个测试先于精细美术效果。

**题：让头发自然晃动，应该修改TTS还是模型物理？** 主要属于角色物理/动画系统；TTS产生声音，可以间接提供节奏，但不负责头发网格约束。

**题：音量嘴型为什么有时“闭着嘴也有声音”？** 可能阈值太高、音频幅度较低或平滑滞后。先查看实际播放采样的能量曲线；不要立即归因于模型质量。
