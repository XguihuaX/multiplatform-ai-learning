# 网页设计：把“高级一点”变成能执行的设计要求

学完这一章，你应当能给AI一份明确的页面任务，判断它为什么不好看，并提出具体修改。我们用一个贯穿案例：为“视频学习笔记库”做介绍页，让首次访问的人点击“阅读示例笔记”。先做内容与页面结构，不要求你先学React。

## 1. 为什么只说“高级一点”通常无效

假设你对AI说：“做一个AI学习网站，要高级、有科技感。”它不知道用户是谁、来这里想解决什么，也不知道什么行为代表成功。于是它容易用渐变、发光、卡片和动效填补信息空白。改了颜色，页面仍然没有说清产品。

先把问题分成三层：

| 层次 | 要解决的问题 | 本例的答案 |
| --- | --- | --- |
| 内容 | 访客为什么需要它？ | 收藏很多视频，却很难回忆步骤和实际使用 |
| 结构 | 应该先回答什么，后回答什么？ | 先展示可读的笔记示例，再说明整理方法 |
| 视觉 | 如何让重要信息更容易被看见？ | 标题、示例、主按钮有清楚的层级 |

如果首屏只有“释放AI潜能”，先改内容。若收益说明埋在页面最底部，先改结构。只有内容和顺序合理后，才处理字号、留白、配色。这样每次修改都有原因。

## 2. 第一步：写一份能指导设计的brief

Brief就是一页任务说明。它不需要专业术语，但必须让设计选择有依据。

本例的完整brief如下，可直接作为练习输入：

```text
项目：视频学习笔记库介绍页（教学演示）
目标读者：收藏了AI工具和课程，却没有时间反复观看的人。
访客最想知道：这里究竟能学到什么，笔记是不是只有空泛摘要。
唯一主要动作：点击“阅读示例笔记”。
提供的内容：概念解释、操作步骤、示例、练习和原始来源。
访问来源：朋友分享，访客此前不了解这个项目。
主要疑问：是否收费？内容来自哪里？我需不需要先安装工具？
已有素材：一篇真实示例笔记，分类目录。
没有的素材：用户评价、节省时间统计、付费价格。
风格：安静清楚、像可阅读的技术手册；手机上也能看。
```

注意“没有的素材”也要写。它告诉AI不要编出“已帮助一万名用户”这种看似有说服力但没有依据的内容。用真实笔记预览证明质量，比虚构好评更合适。

## 3. 第二步：把brief转成页面顺序

这里的落地页是围绕一个主要动作组织的页面。它可以是介绍页，不一定用于卖东西。首页如果要同时承担搜索、个人中心和课程管理，结构会更复杂，本练习先不做这些功能。

本例按访客的疑问组织六段：

1. **首屏：你能获得什么？** 标题、副标题、主按钮和一张笔记预览。
2. **示例：真的能教会我吗？** 展示一小段“概念→例子→步骤”的实际内容。
3. **方法：笔记怎么来的？** 说明视频、字幕、画面和原始文档如何转成教程。
4. **范围：有哪些主题？** 展示知识分类，避免堆满工具名称。
5. **疑问：怎么开始？** 回答是否需要安装、如何找原视频、哪里看尚未核实内容。
6. **结尾：下一步做什么？** 再次提供同一个“阅读示例笔记”入口。

这不是所有网站都必须使用的六段模板。关键是每段回答一个真实问题。重复回答同一个问题的段落可以删掉。

文字线框可以这样画：

```text
[项目名]                                 [分类目录]

把收藏的视频，变成下一次能照着做的笔记
从概念、步骤到练习，打开一篇示例看看。
[阅读示例笔记]

┌──────────────────────────┐
│ 示例：怎样让AI写出清楚的网页？         │
│ 先确定读者和动作，再写结构，最后定样式。 │
│ 练习：改写一个含糊的首屏标题。          │
└──────────────────────────┘

示例片段 → 整理方法 → 知识分类 → 常见问题 → 阅读入口
```

线框阶段只讨论“有什么、放哪里”，不讨论阴影。你可以在纸上完成它。

## 4. 第三步：写出具体的首屏文案

首屏需要让访客快速回答三件事：这是给谁的、能得到什么、下一步点哪里。

| 位置 | 含糊写法 | 本例改写 | 为什么这样改 |
| --- | --- | --- | --- |
| 标题 | AI赋能学习新未来 | 把收藏的视频，变成下一次能照着做的笔记 | 明确对象和结果 |
| 副标题 | 一站式智能知识解决方案 | 从概念解释到操作步骤，按主题阅读视频课程笔记 | 说明交付物 |
| 按钮 | 了解更多 | 阅读示例笔记 | 说明点击后得到什么 |
| 证明 | 效率提升十倍 | 展示一段真实的教程与练习 | 给读者直接判断质量的材料 |

“收益优先”指先写使用者得到什么。比如“支持多模态”是功能，“操作步骤同时对照界面截图，能看清按钮在哪里”才把它和学习任务联系起来。

不要为了写得具体就随意添加数字。“节省80%时间”需要测量；“每篇包含步骤与练习”可以直接通过内容验证。

## 5. 第四步：建立一套小型视觉规则

设计token是可复用的样式值。例如所有主按钮使用同一种颜色，所有正文使用同一字号。它让页面一致，也让修改变简单。

下面是本教程自拟的入门样式，不是原视频规定，也不是通用设计标准：

| 元素 | 示例规则 | 作用 |
| --- | --- | --- |
| 正文 | 16px，行高1.7 | 中文段落易读 |
| 小标题 | 24px，字重600 | 清楚区分段落 |
| 首屏标题 | 手机32px，桌面48px | 保持重点又避免手机挤压 |
| 页面宽度 | 最大1100px，两侧留白 | 宽屏不把文字拉得过长 |
| 间距 | 8、16、24、32、48、64px | 避免每张卡片随意设间距 |
| 颜色 | 浅底、深文字、一个强调色 | 让主动作突出 |
| 圆角 | 卡片16px、内部块8px | 保持形状关系一致 |

你若让AI写网页，可以让它定义为CSS变量，再统一使用：

```css
:root {
  --page-bg: #f7f8fa;
  --text: #18212b;
  --muted: #536171;
  --accent: #176b55;
  --space: 8px;
  --radius: 16px;
}
body { margin: 0; color: var(--text); background: var(--page-bg); }
main { max-width: 1100px; margin: auto; padding: 24px; }
p { font-size: 16px; line-height: 1.7; }
h1 { font-size: clamp(32px, 5vw, 48px); line-height: 1.2; }
```

这些代码的含义：`:root`集中存值；`var(...)`引用值；`max-width`限制内容宽度；`clamp`让标题在给定范围内随屏幕变化。你不必背代码，但应知道要让AI“统一改变量”，而不是让它逐处随机修改。

原项目还有自己的字体、间距和动效规范。学习时要分清：一致性是可迁移原则，具体禁用某种字体或指定某种颜色属于该作者的设计取向。中文项目要另外检查中文字形和实际显示效果。

## 6. 第五步：让交互完整，再增加动效

漂亮截图只能说明静态状态。按钮还需要正常、悬停、键盘聚焦和点击反馈；提交表单则需要处理中、成功和失败状态。

本例只有阅读入口，可以直接使用真实链接。不要生成一个“阅读示例”按钮，却让它指向`#`或什么都不做。若没有用户账号功能，就不要加一个没有实现的“登录”。

动效的任务是解释变化，例如让菜单展开更容易理解。文字连续跳动、阅读前必须等动画结束，会妨碍学习。先做没有动效也能用的版本，再补必要反馈。对减少动态效果的用户设置，应取消不必要移动。

## 7. 如何使用视频里提到的AI Design Skills

当前核对到的仓库是[elayadesign/ai-design-skills](https://github.com/elayadesign/ai-design-skills)。它的`landing-page-design`把需求收集、文案、结构和视觉要求写成可供Agent读取的规则。Skill本身不生成浏览器能力：Agent还要能编辑文件，必要时能运行和检查页面。

在具有终端和Node.js的项目环境中，仓库给出的CLI方式是：

```bash
# 先查看可安装项目
npx skills add elayadesign/ai-design-skills --list

# 安装落地页设计这一项，按提示选择你的Agent
npx skills add elayadesign/ai-design-skills --skill landing-page-design
```

第一次运行可能提示获取CLI。安装后检查工具的技能列表或安装输出，而不是仅看命令返回。此处提供的是官方安装方式，没有在本项目执行安装。

如果宿主只有聊天和自建Skill编辑器，没有终端，你仍可把下一节的完整任务说明用于内容规划；自动创建文件、预览网页等步骤取决于宿主工具。YonWORK中的具体安装路径不能照搬Codex目录。

视频提到的`design-to-motion`在本次查看的主分支技能表中未列出，目前列出的是`landing-page-design`和`figma-designer`。本章先教能直接复用的落地页方法。

## 8. 一段可以直接使用的完整Prompt

```text
请帮我设计“视频学习笔记库”的介绍页。

读者：收藏了AI工具和课程，但很难回忆内容、照着操作的人。
目标：让读者点击“阅读示例笔记”。这是唯一主动作。
内容：概念解释、操作步骤、示例、练习和原始来源。
素材：我会提供一篇真实笔记和分类目录。
没有用户评价、效果统计和收费方案，请不要编造。
风格：清楚安静，适合中文长文阅读，手机也能用。

请按以下顺序工作：
1. 列出你还缺的必要信息；低影响细节可写明假设后继续。
2. 给出页面段落顺序，每段说明回答读者的哪个问题。
3. 写完整首屏标题、副标题、按钮文字，以及示例段落。
4. 给出一套简洁的字体层级、间距、配色和组件状态规则。
5. 先完成首屏，再逐段实现；没有文件工具时输出完整页面说明。
6. 若能运行页面，检查桌面和390px宽手机布局，逐个点击入口。
7. 修改时说明具体问题，例如信息不清、层级不够或按钮无响应；
   不要只把颜色和动效换一遍。

验收：首次访问能看懂用途，示例可直接阅读，主入口有真实目标，
没有编造证据，手机无横向溢出，键盘能聚焦可交互元素。
```

## 9. 练习与参考答案

**练习一：** 把“用最强AI开启智能生产力，立即了解更多”改成面向上面brief的标题和按钮。

参考：标题“把收藏的视频，变成能照着做的笔记”；按钮“阅读示例笔记”。重点是读者和结果明确，按钮指出实际下一步，并不是必须用这几个字。

**练习二：** 页面有三个同样醒目的按钮：“立即注册”“查看示例”“加入社群”。本例应怎样改？

参考：把“查看示例”设为主动作；只有注册确实必要时才保留注册入口；社群可以放次级位置。三者都醒目会让页面目标含糊。

**练习三：** 页面看上去很整齐，但你看完仍不知道能学到什么。应该先调什么？

参考：先换成具体示例和清楚文案，展示一段真实知识与操作步骤。字号和阴影解决不了内容空泛。

完成标准：你能独立写出brief、解释段落顺序、指出一个视觉问题和一个功能问题，并给出具体修改。完成一遍网页生成不等于已经掌握这些判断。
