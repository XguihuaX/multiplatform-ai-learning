# 给角色对话换一个开头：DeepSeek 推理预填充

**原理入门与对照实验设计 · B24**　如果角色卡写着“开朗、体贴”，回复却总在分析用户情绪，可以试着改变模型开始生成的位置。南竹0v0 用“猫娘”做了一个风格很容易辨认的实验。判断效果时要分别看两处：模型生成的推理文本有什么变化，用户实际收到的消息有什么变化。

## 如何理解和接入

前缀续写给模型一段已经写好的开头，让它接下去写。用户消息提供眼前的话题，角色卡提供跨轮设定，推理前缀则为这一次生成提供开场视角。比如“先看看他留了什么悬念”和“先判断用户属于哪类情绪”会把同一个问候引向不同的后续文字。推理文本和最终回复有各自的字段，可以分别观察。片中显示的推理文本只支持对生成文字的分析。

官方 Beta 指南要求使用 `https://api.deepseek.com/beta`，末条消息角色为 `assistant`，并带有 `prefix: true`。指南给的是可见正文前缀示例；API 字段表另行说明思考模式支持用 `reasoning_content` 提供推理前缀。下面是自拟实验的消息体片段，需搭配支持思考模式的模型，开启思考模式，使用自己的 API 凭据。模型版本应随实验记录。[前缀续写指南](https://api-docs.deepseek.com/zh-cn/guides/chat_prefix_completion/) · [字段定义](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)

```json
[
  {"role":"system","content":"你是芙芙，优雅开朗，遇事拎得清。"},
  {"role":"user","content":"猜猜今天发生什么了。"},
  {"role":"assistant","content":"","prefix":true,"reasoning_content":"他把话停在这里，是想让我猜一猜呀。"}
]
```

这里的空字符串让正式台词可以自由开头。应用把返回的 message.content 送给聊天界面或 TTS。实验记录单独区分预先写入的文字和新生成的文字，否则仅凭前缀中已有的语气词就会误判续写成功。

## 用芙芙做一次能判读的实验

1. 准备三条用户消息，分别覆盖留悬念、求安慰、求操作帮助。例如“猜猜今天发生什么了”“刚讲完报告，有点泄气”“我怎么把这段录音导出来”。记录每题期待的行为：接住悬念、照应情绪、给出可行的下一步。
2. 每题开两组独立新会话。A 组只发角色卡和用户消息。B 组保持这两项相同，加同一句通用前缀，例如“先听听他这句话在说什么呀”。用同一前缀测三题，可以发现它会不会在办正事时也让角色过度俏皮。上面的悬念专用前缀可作为后续单独的条件。
3. 固定模型版本、思考模式、历史和生成上限，每题每组请求五次，共三十次。保留报错，成功回复匿名打乱。评审只看用户消息与正式回复，分别判断有无承接具体内容、是否符合角色、任务是否完成。办事场景若缺少软件名称，可以用一个具体澄清问题推进。
4. 例：“你这么卖关子，我猜是之前等的消息终于来了？”给出了猜测，也把话交回用户。“我理解你想分享一件事，请详细描述”传达了基本意图，却没有接住猜谜邀请。这两句是教学示例。统计每组有效样本、报错数和盲评偏好，同时列出失败例；小样本只用于筛选值得复测的方案。
5. 若要检验省 token，另开实验，把长角色卡与短角色卡加前缀对比，记录输入、输出、推理用量及实际账单，先确认自然度和任务完成率可接受。统计时按接口定义处理推理 token，避免把已计入输出的部分重复相加。

**自测**　B 组每次都在推理文本里出现角色口吻，但盲评看不出最终台词有变化，能上线作为改善芙芙台词的依据吗？只能确认推理文本的风格受到了引导。要支持上线，仍需在用户听到或读到的回复上测出收益，并核对失败率与成本。
