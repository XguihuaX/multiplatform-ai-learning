# 从收藏链接找到真正能复用的项目资料

资源导航有价值的地方是缩短定位时间。看完工具展示后，目标应是找到真实项目、适用版本和使用入口，形成以后AI可以直接读取的知识条目。

## 1. 先确认项目身份

相似名字不一定指同一项目。优先从视频画面或作者说明提取完整仓库地址，再核对仓库作者、README截图与功能。例如X27画面给出 `elayadesign/ai-design-skills`，这比仅搜索“神级网页Skill”更准确。

稳定ID用于识别同一素材，仓库地址用于识别项目，版本用于识别当时的实现。三者分开保存：同一项目可能被多条视频介绍，一条视频也可能介绍多个项目。

## 2. 阅读官方资料的顺序

先看用途和示例，判断输入输出；再看安装条件，判断机器或宿主能否运行；再看API或具体Skill文件，确定怎样调用；最后对照版本说明和授权条件。每一步都回答一个实际问题，不需要无目的读完整个仓库。

以网页设计Skill为例，需要知道它提供哪些技能名、需要什么宿主、调用时应给什么设计需求。以TTS为例，需要知道音色如何注册、请求字段、输出音频格式和采样率。

## 3. 一条真正有用的收藏记录

```text
项目：AnifLive-TTS
用途：将文本转为可流式接入应用的语音。
关键机制：常驻推理、预热、推理后端优化、PCM流式输出。
输入：已注册模型/声音、文字、语言、生成设置。
输出：完整WAV或原始PCM；按真实API处理格式。
应用：学习笔记讲解器；需另做LLM、分句队列和取消逻辑。
复用入口：本仓库语音教程＋官方API。
版本与条件：与性能数字一起保存，不只抄标题。
```

记录的价值在于后来看到它就知道可以怎样接到自己的项目。来源链接、核查日期可以放在末尾，避免正文被登记字段占满。

## 4. 给后续 AI 的检索要求

让AI先按知识类型找到教程，再根据教程中的原始链接核对当次实现需要的版本信息。写代码时优先使用已经核实的接口；材料缺少字段时明确查哪份API文档。不要让AI仅凭收藏标题补出安装命令。

练习：如果有一个“最强配音工具”收藏，没有仓库地址，下一步是什么？先找完整项目身份与具体输出，确认是网页服务、开源模型还是第三方整合包。此时仍可保存展示效果，但不能把名称猜测写成部署教程。
