# Agent记忆与持续运行

这批收藏同时包含记忆概念展示（B05/B06）、有代码入口的SurfCore（B18）、编码自我介绍（B22），以及已核对原口播的管理经验（X23）。证据深度不同，暂不能将它们排成统一性能榜。

[SurfCore README](https://github.com/Mieksido/surfcore)目前最适合拆解工程结构：多渠道事件进入同一个角色身份，结合记忆持久化、遗忘和时间调度形成持续行为。学习时先画数据流，而不是沿用标题中的意识词汇。部分桌面形象依赖独立软件，需要单独核实。

可用于分析其他项目的问题：

1. 什么事件触发记忆写入？是原始日志、摘要还是结构化事实？
2. 什么任务触发检索？返回哪些记录，如何处理冲突和过期信息？
3. 主动行为由定时器、事件还是未完成任务触发？
4. 中断后从哪里恢复，如何判断任务已完成？
5. 多Agent共享哪些状态，如何防止重复工作？

这是本库的阅读框架，不是对未读视频的机制复述。B05/B06仍需要原视频支持；X23的七项方法已按原口播核对，见下文。

实践建议：用虚构个人偏好与三个小任务建立事件日志，测试跨会话检索、偏好修正和中断恢复。保存输入、检索结果和最终动作，分别评估记住了什么与正确执行了什么。

## 三种不同的“记忆”

- **模型研究中的记忆接口（X10）**：文本检索入prompt、隐状态向量注入、输出token分布调整是不同路径，不能统称为同一插件。视频中的新方法只在小模型与虚构事实上探索，公平基线仍在修订。
- **项目记录（X20）**：偏好、决策、任务和结果链接保存在文件中，任务前检索。卡片提出日整理周复盘，但没有展示调度实现。
- **运行上下文（X18）**：每一步选择当前任务真正需要的信息，必要时压缩并保存可恢复状态。不能将向量库、KV cache、文件记忆混成同一机制。

## 七项管理建议如何取舍

X23原口播完整七条为：总管角色、少而精、成功后保存Skill、独立工作账号、减少人工搬运、补齐背景、语音描述后复述确认。优先采用后四项中的流程固化、背景说明和交接改进；只有确实存在多个独立任务时再评估总管。视频中的自动巡检不代表宿主已提供定时执行。

把一次成功保存为Skill之后，用第二个不同输入验证它是否可复用；记录触发条件、输入、步骤、验收与失败处理。账号与消息发送仍按实际任务授权配置，不根据视频推广自动创建。
